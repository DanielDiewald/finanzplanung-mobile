Capyt 2.2.4a – PWA Hotfix Test Results
=======================================

PWA-Ursache
-----------
Die Versionsvalidierung in js/pwa-update.js akzeptierte normales SemVer,
aber nicht das in Capyt verwendete Alpha-Schema wie 2.2.3a / 2.2.4a.
Dadurch wurde version.json als ungueltig verworfen und der iOS/PWA-spezifische
versionsbezogene Service-Worker-Updatepfad nicht genutzt.

Zusaetzlicher Deployment-Blocker
--------------------------------
Der GitHub-Pages-Workflow fuehrt `npm test && npm run check` aus. Im bisherigen
Stand blockierten veraltete Visualisierungs-/PWA-Tests sowie ein Static-Check,
der ein nicht aktiv verlinktes Root-Manifest pruefte, die Veroeffentlichung.
Die Tests wurden an das vorhandene aktuelle Verhalten angepasst und der
Static-Check prueft jetzt das tatsaechlich in index.html verlinkte Manifest.

Fixes
-----
- Alpha-Versionen wie 2.2.4a werden als gueltige Online-Version akzeptiert.
- registration.update() bleibt als expliziter Fallback erhalten.
- pwa-update.js verwendet fuer den Hotfix den Cache-Buster 2.2.4a-pwa1.
- Das aktiv verlinkte Manifest nutzt GitHub-Pages-taugliche relative Icon-Pfade.
- Die Manifest-Icons sind im Service-Worker-Precache enthalten.
- Der Static-Check validiert das wirklich verlinkte Manifest und dessen Icons.
- Veraltete Tests pruefen wieder das aktuelle Verhalten statt alte Defaults.

Tests
-----
- npm test: 86/86 bestanden
- npm run check: bestanden
- PWA-spezifische Tests: 5/5 bestanden
- JS-Syntaxcheck fuer js/pwa-update.js: bestanden

Version
-------
Sichtbare App-Version bleibt 2.2.4a (PWA-Hotfix).
